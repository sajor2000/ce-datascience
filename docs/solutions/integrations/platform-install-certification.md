# Platform Install Certification

`ce-datascience` is authored as a Claude Code plugin and also ships generated
layouts for target platforms that do not consume the Claude plugin directly.
Before releases that touch converters, writers, manifests, or plugin content,
run temp-root installs for each implemented generated target and verify the
installed files are self-contained.

## Platform Contracts

- Claude Code is the source plugin format. Claude subagents are Markdown files
  with YAML frontmatter under `.claude/agents/` or `~/.claude/agents/`, and
  plugin content should stay compatible with that shape.
- Codex native plugins load skills from `.codex-plugin/plugin.json`; generated
  Codex output is an agent bridge until plugin-defined agents are native.
- OpenCode loads skills from `.opencode/skills/<name>/SKILL.md` or compatible
  Claude/agent skill paths, and custom agents/config are generated by the CLI.
- Pi uses generated `.pi/` skills, agents, prompts, extensions, and MCPorter
  config. The subagent and ask-user extensions remain external prerequisites.
- Gemini CLI and Qwen Code have native extension systems. Qwen can install and
  convert Claude Code marketplace plugins directly, so `qwen` is a native
  install target rather than a generated `--to qwen` converter target.
- Kiro uses generated `.kiro/` agents, skills, steering files, and `mcp.json`.

## Required Checks

- Run the real `install` command into OS temp roots for `codex`, `opencode`,
  `pi`, `gemini`, and `kiro`.
- For Codex, test both the recommended native-plugin-plus-agent-bridge mode and
  standalone `--include-skills` mode.
- Confirm local MCP server entries point at absolute installed files, not the
  source checkout or a temp clone that may disappear after install.
- Confirm generated outputs do not include `__pycache__`, `.pyc`, `.pyo`, or
  `.DS_Store` artifacts.
- Confirm reruns clean artifacts that the same plugin previously managed
  without touching same-named user files or other plugins.
- Confirm skill instructions invoke bundled scripts through skill-local paths
  such as `python3 scripts/tool.py` or `bash scripts/tool`, never source-repo
  paths like `plugins/ce-datascience/skills/...`.
